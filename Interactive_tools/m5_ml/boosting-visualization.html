Rows with big residuals are where the model is most wrong, so GOSS always keeps them. From the rest it takes a small random sample and scales it up by (1 − a)/b, so totals stay roughly right. The error mass tiles show what share of all the absolute residual the sampled rows carry, GOSS against a plain random sample of the same size. GOSS pays off most when a few rows hold most of the error, which is common in large, messy data. Airline residuals are spread fairly evenly, so here the gain is modest.

1 · Start from the average

Round 0 predicts the average target for every row. Here that is last month's passengers grown by the average monthly change, which lags the seasonal swings badly.

2 · Fit what's left

Each new tree is trained on the current residuals, the negative gradient of squared error. Its answer is shrunk by η and added on. Small trees and a small η make many careful steps instead of a few big ones.

3 · Stop early

Training error only goes down. Test error does not. Choose the number of rounds on a validation window that comes after the training data, never by looking at training error.

4 · Boosting vs bagging

Boosting adds shallow trees in sequence to cut bias, so stumps work well here. Bagging averages deep trees in parallel to cut variance, where stumps barely help. Neither can extrapolate a trend, so both need a stationary target.

Data: Box and Jenkins monthly international airline passengers, January 1949 to December 1960, thousands. Rows start in April 1950 so every lag exists. With the monthly log change target, gt = log Pt − log Pt−1, the features are the calendar month, gt−1, gt−2 and gt−12, and the forecast is P̂t = Pt−1 · eĝt. The raw target uses Pt−1, Pt−2, Pt−12 and the month. Model: plain gradient boosting with squared error, level-wise trees, no other regularization. Histogram bins are equal width over each feature's training range. Real LightGBM also grows trees leaf-wise and bundles sparse features, which this page leaves out.
