Holt-Winters Method (Additive Seasonality)

This tool steps through the Holt-Winters additive method one period at a time, re-estimating the level, trend, and twelve monthly seasonal indices as each new observation arrives and folding them into a forecast. Drag the smoothing parameters or set your own starting level, trend, and seasonal values to see how each choice reshapes the fitted curve and the components behind it.

🎯 Forecast Equation

ŷt+h|t = ℓt + h·bt + st+h-m(k+1)
Level + trend + seasonal, with k = floor((h−1)/m). That picks the latest seasonal of the target month, including past the first year of the forecast.

📊 Level Equation

ℓt = α·(yt - st-m) + (1-α)·(ℓt-1 + bt-1)
Deseasonalized smoothing

📈 Trend Equation

bt = β*·(ℓt - ℓt-1) + (1-β*)·bt-1
Trend smoothing (same as Holt)

🌊 Seasonal Equation

st = γ·(yt - ℓt-1 - bt-1) + (1-γ)·st-m
Updates seasonal factor for current period

⭐ What does "Find the Best Fit" do?

It asks one question: which values of α, β*, and γ make the one-step-ahead forecasts fit the training months best? For every candidate it runs the same recursion you watch in the animation across the 115 training months, adds up the squared errors between each forecast ŷt and the actual yt, and keeps the candidate with the smallest total (the SSE). That is exactly the criterion statsmodels and R's ets() use when errors are additive, and the search below keeps to statsmodels' default parameter region, so the answer you get here is the answer you would get in Python.

  • Starting values. By default the initial level ℓ0, the initial trend b0, and the twelve initial seasonal indices are estimated as well, not just the smoothing parameters. This needs no extra searching because the forecasts depend linearly on the starting values, so for any candidate α, β*, γ the best starting values are an ordinary least-squares solution. The seasonal indices are constrained to sum to zero, otherwise a constant could be moved freely between the level and the seasonals and the answer would not be unique. Tick "keep my starting values fixed" to search only over the smoothing parameters and keep the sliders where you set them.
  • Allowed region. The search uses the default parameter region of statsmodels: 0 ≤ α ≤ 1, 0 ≤ β* ≤ α, and 0 ≤ γ ≤ 1 − α. The cap on γ keeps the seasonal update from double-counting a surprise the level has already absorbed, and Hyndman's usual region has it too. The cap on β* is a statsmodels default rather than a textbook rule (Hyndman's usual region only asks for 0 ≤ β* ≤ 1). Results are snapped to the sliders' 0.01 grid.
  • Training only. The test months play no part in the search. A lower training RMSE does not guarantee a lower test RMSE, and comparing the two after clicking the button is the point of the exercise.

What to look for. This is the first model in the suite where the optimizer finds something clearly better than a hand-tuned fit, because the seasonal component is what the airline data actually need. Notice that the answer lands on the boundary γ = 1 − α: the data want the seasonal indices to adapt as fast as the rules allow. Then tick "keep my starting values fixed" and search again to see how much the estimated starting values are worth on their own.

📚 Parameter Guide: Understanding Alpha (α), Beta* (β*), and Gamma (γ)

🎯 Triple Parameter Control: Level, Trend, and Seasonal Components

📊 Alpha (α) - Level

Deseasonalized level adaptation:

  • Low α: Stable, noise-resistant
  • High α: Quick adaptation

📈 Beta* (β*) - Trend

Trend direction changes:

  • Low β*: Stable trend
  • High β*: Adaptive slope

🔄 Gamma (γ) - Seasonal

Seasonal pattern evolution:

  • Low γ: Fixed seasonality
  • High γ: Evolving patterns

🎯 Complete Forecast: ŷt+h|t = ℓt + h·bt + st+h-m(k+1)

The forecast combines all three components: current level + trend × horizon + appropriate seasonal factor.

  • Level (ℓt): Where the deseasonalized series currently is
  • Trend (h·bt): Linear growth component extending into future
  • Seasonal (st+h-m(k+1)): Cyclical pattern repeating every 12 months

⚡ High γ Benefits

Seasonal patterns can evolve over time. High γ allows adaptation to changing seasonal behavior (e.g., climate change affecting tourism patterns).

⚠️ High γ Risks

Too-responsive seasonal factors can overfit to noise, creating unrealistic seasonal fluctuations that don't represent true patterns.

🔬 Deseasonalization Process

The key insight: ℓt = α·(yt - st-m) + (1-α)·(ℓt-1 + bt-1). By removing the seasonal component before updating the level, Holt-Winters prevents seasonal peaks from being confused with genuine level changes. This separation enables each component to capture its own distinct pattern in the data.
